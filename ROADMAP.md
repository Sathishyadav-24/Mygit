# Development roadmap

These are proposed steps, not completed milestones. Adjust their order and scope as the project takes shape.

## 1. Define a small project

- [ ] Complete the [project brief](docs/project-brief.md): identify the problem, intended users, platform, and desired outcome.
- [ ] Choose one useful first feature and write clear acceptance criteria.
- [ ] Decide what is out of scope for the first version.

## 2. Set up the chosen tools

- [ ] Choose the language, frameworks, and structure that fit the project; document the decision.
- [ ] Add the first source files and extend `.gitignore` for generated files and dependencies.
- [ ] Document prerequisites, installation, configuration, and how to run the project in the README.
- [ ] Choose a license and contribution terms before inviting external reuse or contributions.

## 3. Build and verify the first feature

- [ ] Implement the smallest usable version of the chosen feature.
- [ ] Add tests for its key behavior and document how to run them.
- [ ] Test on the intended platform and record any remaining limitations.

## 4. Prepare a first release

- [ ] Add appropriate automated checks, such as build and test checks, once the stack is known.
- [ ] Document the release or deployment steps for the chosen platform, including configuration and secret handling.
- [ ] Verify the release in its target environment and note how to recover if a release fails.
